# Private Integration handoff

## OAuth

- Redirect URI: `https://sinaichannel.ru/oauth/callback`
- OAuth client ID / client UUID: use the value generated by the new Private Integration as `AMOCRM_INTEGRATION_ID`.
- Secret key: use the value generated by the new Private Integration as `AMOCRM_CLIENT_SECRET`.
- Do not configure `secrets_uri` for this replacement flow.

The existing callback accepts an authorization `code`, exchanges it at `/oauth2/access_token` with the configured client ID, secret and redirect URI, and saves only the resulting tokens in the encrypted SecretStore.

## Widget archive

Create `widget.zip` from the *contents* of `artifacts/amo-private-widget` (not from its parent folder). The archive must contain:

```text
manifest.json
script.js
i18n/ru.json
README.md
```

The widget has exactly one location: `lead_sources`. Its script is a no-op and has no Telegram credentials or business logic.

## amoCRM fields and channel registration

- Integration type: Private Integration with widget archive.
- OAuth redirect URI: `https://sinaichannel.ru/oauth/callback`.
- Widget location/capability: `lead_sources`.
- Enable the integration's **multiple sources** capability before production migration.
- Give amoCRM Support the private integration's **integration ID / client UUID** and the generated **widget code**. Ask Support to set both on the existing `SinaiTelegram` Chats Channel and retain Write First.
- Do not use the OAuth client UUID as the widget code unless amoCRM explicitly generated them as the same value.

No production `.env`, account lifecycle, source lifecycle, or current External Integration is modified by these preparation files.
